# 数据生产指南

### 一、 6G 仿真 Pipeline 的核心架构

你的 Python 代码应该遵循 **“拓扑生成** $\rightarrow$ **资源初始化** $$\rightarrow$$ **业务流注入** $$\rightarrow$$ **状态演化**  $\rightarrow$  **快照采集”** 的流程。

1. #### 模块一：分层异构拓扑生成 (Hierarchical Heterogeneous Topology)

目标： 解决“资源分布的跨子网性”和“拓扑结构差异”。

Python 工具： NetworkX

如何体现 6G 特性：

- **分层结构：** 你的图不能是一个简单的随机图。必须包含 **云（Cloud）- 网（Core/Transport）- 边（Edge）- 端（Device）** 的层级。
- **非地面网络 (NTN) 扩展：** 6G 强调空天地一体化。你需要在拓扑中随机加入“卫星节点”或“无人机（UAV）节点”，这些节点的连接关系是动态变化的。
- **多样性策略：**
  - 核心网使用 `barabasi_albert_graph` (无标度网络，模拟少数枢纽节点)。
  - 边缘接入网使用 `random_geometric_graph` (基于地理距离连接，模拟基站覆盖)。

1. #### 模块二：多维资源关联初始化 (Correlated Attribute Initialization)

目标： 解决“异构、高维、多源”资源特征。

Python 工具： Numpy, Scipy.stats

注意事项：

- **避免完全随机：** 真实世界中，CPU 强的节点通常带宽也大（云服务器），而 CPU 弱的节点带宽也小（IoT 设备）。你需要使用 **协方差矩阵 (Covariance Matrix)** 来生成具有相关性的多维资源数据。
- **长尾分布 (Long-Tail Distribution)：** 6G 网络中大部分节点是轻量级的（边缘/终端），少数是高性能的（云）。使用 **帕累托分布 (Pareto Distribution)** 或 **对数正态分布** 来初始化资源容量，而不是正态分布。
- Python

```Plain
# 示例：生成符合长尾分布的 CPU 容量
cpu_capacities = (np.random.pareto(a=3.0, size=num_nodes) + 1) * base_cpu
```

1. #### 模块三：时空动态业务流生成器 (Spatio-Temporal Traffic Generator)

目标： 解决“双时间尺度”和“潮汐效应”。

Python 工具： SimPy (离散事件仿真)

如何体现 6G 场景：

- **多类型业务 (SLA Awareness)：** 必须生成不同意图的业务 (6)。
  - **URLLC (自动驾驶)：** 极低时延要求，小包，高优先级。
  - **eMBB (全息会议)：** 极高带宽要求，大包，持续时间长。
  - **mMTC (传感器)：** 海量并发，极小资源需求。
- **时空潮汐 (Tidal Effect)：** 业务到达率 $$\lambda$$ 不能是常数。它应该是时间的函数 $$\lambda(t)$$（例如正弦波模拟早晚高峰），且在空间上移动（例如：早晨流量集中在居住区子网，白天集中在工业区子网）。

1. #### 模块四：状态演化与交互引擎 (Interaction Engine)

目标： 产生用于对比学习的“动态变化” 。

核心逻辑：

- **资源消耗与释放：** 当业务到来，扣除对应路径上的带宽和节点的 CPU；业务结束，触发“资源回收” (8)。
- **随机扰动 (Perturbation)：** 为了增强模型的鲁棒性（这也是 MM-CLR 需要的），你需要模拟故障：
  - *链路抖动：* 随机给某些边的 Latency 增加 50ms。
  - *节点失效：* 随机将某个边缘节点的 Capacity 设为 0（模拟宕机）。

1. #### 模块五：全景快照采集器 (Snapshot Recorder)

目标： 生成 JSONL 格式的训练数据，满足“统一感知与表征” 9。

操作： 设定一个全局时钟步长（例如每 1 秒），暂停仿真，遍历 NetworkX 的图对象，提取所有节点属性和边属性，写入文件。

### 二、 关键注意事项 (Pitfalls to Avoid)

为了让数据被顶会认可，你需要特别注意以下几点：

1. #### 不要使用“静态快照” (Don't use static snapshots only)

背景： 很多论文只生成一堆不相关的图。

6G 要求： 你的数据必须具备时序相关性。第 $$$$ 秒的拥塞必须是第 $$t-$$ 秒业务累积的结果。

**做法：** 务必使用 `SimPy` 运行连续的时间轴，而不是用 `for` 循环生成独立的随机图。这呼应了任务书中的“状态演化规律” 

1. #### 必须体现“算网融合” (Compute-Network Convergence)

背景： 传统网络论文只看带宽，云计算论文只看 CPU。

6G 要求： 任务书明确指出资源包括“计算、存储、网络” 。

做法： 在数据中，一个任务的失败，既可能是因为链路带宽不足（网络瓶颈），也可能是因为节点排队太长（计算瓶颈）。你的数据必须包含这就两种失败案例，多通道注意力机制才能学到东西。

1. #### 增加“噪声”与“异常” (Noise & Anomalies)

背景： 过于完美的数据会导致模型过拟合，且不符合真实环境。

做法：

- 在链路时延中加入高斯白噪声。
- 模拟“突发流量 (Burst)” (12)：在某个短时间内，让  $$\lambda$$  突然翻 10 倍，创造极端的长尾样本。这是检验模型泛化能力的关键。
